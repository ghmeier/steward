# Consolidate game copy into src/core/copy.ts

Research: `.apl/research/tui/2026-11-11-game-copy.md`

## Goal

Every hardcoded player-facing string lives in `src/core/copy.ts`, so a writer can read and edit all the game's wording in one place. Strings that need values are template functions. The text in `data/*.json` stays where it is. The header of `copy.ts` points to it.

## Approach

### Shape of `src/core/copy.ts`

- The module exports one `as const` object, `copy`, with a section per area of the game: `crown`, `illusion`, `desk`, `notices`, `ledger`, `village`, `court`, `menus`, `help`, `keys`, `commandLine` and `decrees`. Section order follows what the player meets first. Each PR fills its own sections, which keeps parallel PRs from editing the same lines.
- Static text is a plain string property: `copy.illusion.cannotConjureYet`.
- Text that needs values is an arrow function taking one named-argument object, so the template reads like the sentence it produces:
  ```ts
  oneSeasonLeft: ({ amount, resource }: { amount: string; resource: string }) =>
    `One season left to deliver ${amount} ${resource} to the crown.`,
  ```
- Arguments are already formatted strings, or plain numbers when the copy itself decides the grammar. Formatting helpers (`plain`, `formatTicks*`) stay in `src/tui`, because core cannot import them and the copy file should not own number formatting.
- Plurals go through a small `plural(count, one, many)` helper in `copy.ts`. Lists like "a, b and N others" stay as one template function.
- Prose that names a key takes that key as an argument, for example `archiveOpens({ key })`. The call site passes the binding from `keys.ts`.
- The only imports allowed in the module are types (for example `Resource`). It contains no logic beyond string assembly.

### What does not move

- Command tokens that the parser matches against input.
- Layout code: `padEnd`, column widths and joins.
- Developer-facing errors and validation issues.
- Text in `data/*.json`.

### Tests

Tests verify behavior, not wording. A copy edit should never require a test edit.

- Delete tests whose only purpose is to pin wording.
- When a behavior test needs to know which message appeared, it references the `copy` object instead of a literal, for example `expect(frame).toContain(copy.notices.archiveOpens({ key: "a" }))`. Better still is a structural check: the notice is non-null, the row exists, the rejection has `ok: false`.
- Do not assert on substrings of a sentence, such as `toContain("crown")`, as a proxy for which message appeared.
- Each PR applies this to every test of the files it touches.
- Add one `copy.test.ts` that holds two invariants:
  - every template returns a non-empty string with no unfilled `${` or `{name}` placeholder;
  - no copy string contains a key letter that disagrees with `keys.ts`. Include this only if it stays cheap; otherwise drop it.
- The validation command is `bun run check`.

## Review patterns

- No comments in `copy.ts` beyond the header and a why-comment on any odd grammar choice. No section banners.
- Template argument names describe the value, such as `amount`, `resource` or `wait`, never `a` or `s`.
- Do not reword any copy during the move. Moving text and editing it are separate changes.

## Risks

- **Parallel PRs touching `copy.ts`.** PR 1 predeclares the sections, so each later PR edits a separate region. Any rebase conflicts should be trivial.
- **Some copy is built from tuning data**, for example the help lines that compute rates. Those become template functions that take the formatted numbers. The computation stays in `help-menu.ts`.

## Notes and decisions

- 2026-11-11: The user chose to move only hardcoded TypeScript strings. The text in `data/*.json` stays.
- 2026-11-11: `copy.ts` lives in `src/core/` because of the core import boundary.
- 2026-11-11: The user asked for PRs to be split by change area, not by risk; there are no outside players to protect. Each PR covers one area of the code, and only the shared `copy.ts` scaffold sets the order.
- 2026-11-11: The user approved the plan and added that tests must not verify exact copy. Tests that only pin wording are deleted, and the remaining tests check behavior.
