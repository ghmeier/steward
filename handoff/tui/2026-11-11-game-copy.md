# Game copy consolidated into src/core/copy.ts

Continues `plan/tui/2026-11-11-game-copy.md`. Research: `research/tui/2026-11-11-game-copy.md`.

## Context

The goal was to make all the game's player-facing wording easy to read and edit in one place, with template functions where text needs values.

The scope was hardcoded TypeScript strings only. Content text in `data/*.json` stays next to the numbers it describes: crown lines, desk dispute templates, Archive labels and descriptions, and peasant names.

## Done

### What we built

`src/core/copy.ts` exports one `as const` object, `copy`. Its sections follow the order a player meets them: `crown`, `illusion`, `desk`, `notices`, `ledger`, `village`, `court`, `menus`, `help`, `keys`, `commandLine`, `decrees`.

- **Static text** is a string property, such as `copy.crown.noDemand`.
- **Text that needs values** is an arrow function taking one named-argument object, such as `copy.notices.starved({ names, deaths })`. Arguments are already formatted strings. They are numbers only where the copy decides the grammar, through the `plural(count, one, many)` helper.
- **The file is pure string assembly.** It imports types only, and has no number formatting or layout.
- **It lives in `src/core/`** because core code may import only from `src/core/`, as `core-boundary.test.ts` enforces. Core rejection reasons are player-facing.

### Key files

| File | Role |
|---|---|
| `src/core/copy.ts` | All hardcoded player-facing wording |
| `src/core/copy.test.ts` | Walks `copy` and renders every entry. Each must be non-empty with no leftover `${` or `{name}` placeholder. Also holds the `plural` test. |
| `src/tui/keys.ts` | Adds `keyFor(panel)`, `peasantKeyFor(job)` and `panelHintKey(panel, label)`, so prose that names a key takes it from the bindings |
| `test/helpers.ts` | `topicLines(id, using, unlocks)` replaced `topicText(heading)` for asserting Help topic lines |

## Next steps

These are optional follow-ups the work surfaced:

- `copy.village.emptyVillage` still hardcodes "Press n". It should take the key from the bindings, as `copy.notices.archiveOpens` already does.
- `core/commands.ts` forwards thrown `Error` messages to the player. One example is the peasant "already works the ..." message from `core/delegates.ts`. Invariant errors should not reach the player as copy.
- A panels and menus test checks a slice of a desk dispute line from `data/desk.json`. Editing that dispute line would break it, so it could become a structural check.

## Gotchas

- **Tests verify behavior, not wording.** This is the user's rule. Never assert a literal player-facing sentence or a substring proxy for one. Compare against `copy`, or check structure instead.
- **Command tokens are grammar, not copy.** Suggestion `.text` values, and words the parser matches ("when", "otherwise", "not", "above", "below", "owed", "and", "or"), stay in `command-line.ts` and `decree-format.ts`.
- **Layout stays at the call site.** That includes `padEnd` widths, row prefixes and joins. Unit suffixes (`/s` and ` s`) also stay at the call site, in the help menu's formatting helpers.
- **Non-string template arguments need a sample.** A template argument that must be a non-string (a list, or a number used for grammar) needs an entry in `NON_STRING_ARGUMENTS` in `copy.test.ts`. Currently those are `names`, `deaths`, `entryId` and `moves`. Every other argument is sampled as a string.
- **Reuse an entry when two sites say the same sentence.** For example, `copy.crown.noDemand` is used by both the crown and the illusion code.
