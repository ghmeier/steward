# Phase 9 merged: ending a posting, doctrines, provinces and followers

## Context

This continues [[plan/prestige/2026-11-23-phase-9]], which is now completed. The research is in [[research/prestige/2026-11-23-phase-9]], and the work follows [[handoff/playtest/2026-11-12-governors-playtest-done]].

Phase 9 of the [development plan](https://claude.ai/artifact/W1LESSbnonaotUx1qEu93J) is prestige. A career now runs from the village into a second posting and beyond. All of it is on `main` at 3837c5e. The save schema is version 20.

## What we built

### Ending a posting

- **When the player can end it.** Once 6 crown demands have been met in the posting (`data/prestige.json`), the Crown panel says so, and `e` opens the posting-end screen. The screen goes through three steps:
  1. A summary of the ending and of what carries over and what resets.
  2. The doctrine list.
  3. The name prompt.
- **A core rule.** The `endPosting { name, doctrine }` command is applied in `step`, so replays reproduce it. Core refuses it before the milestone. Unlike panel gates, this is a game rule, not a screen gate.
- **The ending follows the crown favor band:**
  - warm is a promotion, which takes the kinder of two province draws
  - neutral is a reassignment, which draws once from all four provinces
  - cold is a scandal, which draws from the harsh provinces
- **Archive scope.** Archive entries have a `scope`.
  - The 20 posting-scoped entries reset: the stores, tools, `market.rights`, `lenders.favor`, `court.friends`, `governors.physician` and `governors.slots`.
  - Career entries and `career.seen` persist, so the reset entries reappear in the Archive at their original prices.
- **The next posting starts with:**
  - promotion already done, and the Crown charter owned
  - 12 peasants, grain 200, wood 60 and ore 20
  - its first crown demand scheduled explicitly from the start tick
  - crown favor at 0
- **Seeds.** Posting N's seed is `nextU32(seedStream(previousSeed, "posting:<index>"))`.
- **History.** `career.postings` keeps a record of each posting. It holds index, name, province, doctrine, `startedAt`, `endedAt`, ending, favor, and demands met and missed. The current posting has `index`, `startedAt`, `province` and `doctrine`. Posting 1 has `""` for both province and doctrine.
- **The tick stays global.** Nothing is rebased.

### Doctrines, provinces and escalation

- **Doctrines** are in the `doctrines` section of `data/doctrines.json`. Each is a bundle of modifiers plus one rule:
  - **Trade:** sell price ×1.25 and farm yield ×0.9. Its rule is `payInCoin`: the `pay` verb, or `c` on the Crown panel, pays a grain, wood or ore demand in coin at the market price ratio. Payment can be partial, and conjured coin counts.
  - **Agriculture:** farm yield ×1.2, grain cap +125 and mine yield ×0.8. Its rule is that harvest grain lost to the cap goes to the next peasant's progress. `add()` in `src/core/math.ts` returns the amount the cap turned away.
  - **Extraction:** mine and forest yield ×1.2, and farm yield ×0.85. Its rule is prospecting: each season end pays 0.5 coin per ore mined that season, counted in `economy.seasonOre`, and only an extraction posting counts it.
- **Provinces** are in `data/prestige.json`:
  - Fertile valley and Timber march are kind.
  - Poor soil and Entrenched nobles are harsh.
  - Each province has modifiers and an escalation factor between 1.0 and 1.15.
- **One modifier path.** Doctrine and province effects go through the same `UnlockManager.modifier` path as Archive entries. Gap modifiers, the ones that add instead of multiply, can now be negative.
- **Escalation.** The factor is `(1 + 0.25 × (index − 1)) × province factor`.
  - Crown demand base amounts are multiplied by it.
  - The audit debt share is divided by it, so later postings get sharper auditors.

### Governors who follow

- **Loyalty.** Each governor has a `loyalty` score that never goes below 0. The numbers are in `data/governors.json`:
  - +1 per season served
  - +3 for serving through a backed audit
  - −5 when the crown misses a demand
  - a dismissal after a failed audit leaves loyalty at 0
- **Who follows.** At `endPosting`, up to 2 governors with loyalty 6 or more follow.
  - Ties go to the earliest `hiredAt`, then the lower id.
  - Followers are stored in `career.followers` as name, traits and loyalty.
  - They are seated before the new posting's peasants are named, with new ids, terms and villages, and seating ignores the governor cap.
- **On screen.**
  - Governor rows read "wary of you" below 3, "steady" from 3 to 5, and "devoted to you" at 6 or more.
  - The posting-end screen names who will follow.

### Tests and runner

- **Simulations are opt-in.** Strategy simulations live in `src/runner/strategies.sim.ts`, which runs with `bun run test:sim`. Neither `bun test` nor `bun run check` runs them, which Garret asked for.
- **Fast coverage in the default run.** Game rules are covered by fast tests that build the state directly. `servedVillage` and `endPosting` in `test/helpers.ts` build a village at the milestone and end the posting.
- **Speed.** The default `bun test` takes about 2.5s in parallel.
- **Runner.**
  - Strategies take `laterPostings: [{setup, purchases, doctrine?}]`, where the last entry repeats.
  - A strategy with any later postings ends each posting as soon as the milestone is reached.
  - `sim.ts` reports outcomes for each posting.

## Gotchas

- **Simulations stay out of the default run.** Don't add strategy or long simulation runs to `bun test`. Build the state directly, for example with `servedVillage()`, and put long runs in `strategies.sim.ts`.
- **Test helpers' governor names depend on file order.** `governorOf` in `test/helpers.ts` names governors from a counter shared across test files, so names differ between local and CI runs. Don't assert on a specific governor's name being absent, because a new peasant can draw the same name. This caused #42's one CI failure.
- **The golden file can't reach the milestone.** It grants every entry at tick 0, so the crown never schedules a demand. Replay across a posting boundary is covered by a record-then-replay test in `strategies.sim.ts`, plus a fast one in `prestige.test.ts` that starts from a constructed state.
- **Old command logs.** `endPosting` requires `doctrine`, so an old command log with an `endPosting` and no doctrine won't parse. None are persisted today.
- **Hoard seizure.** Nothing in the game seizes a hoard. A dismissal after a failed audit is the only forced handover, and it is what zeroes loyalty.
- **Panel tests.** The Crown panel's key row is full. The `c` hint for paying in coin is a body line shown only in a trade posting.
- **Gap modifiers can be negative**, but factor modifiers must stay above zero.
